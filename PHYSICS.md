# Project Nebula Physics Foundations

This document defines the canonical physics model for Project Nebula.

The operational hierarchy is:

```text
Signals
-> Resource Transformations
-> Trajectories
-> Emergent Identities
```

Identities are no longer primary entities in the conceptual model. They are emergent structures produced by sustained trajectory patterns over time. The existing identity-vector system remains active as the current compatibility implementation of the emergent identity layer.

## Ontology

### Signal

A signal is the smallest observable unit of behavior.

Examples:

- Studied English for 30 minutes
- Worked on authentication module
- Trained at the gym
- Met with coffee supplier

Signals remain the primary input into Nebula. Signals generate resource transformation evidence.

### Event

An event is an observable occurrence that provides context.

Examples:

- Took English certification exam
- Signed coffee shop lease

Events do not directly build identity. Events provide evidence that can contextualize or validate transformations and trajectories.

### Result

A result is an outcome generated by previous signals.

Examples:

- Passed English exam
- Generated $500 profit

Results do not directly build identity. Results validate trajectories already observed.

### Resource

A resource is a transferable capacity.

Initial resource set:

- `time`
- `energy`
- `attention`
- `money`
- `knowledge`
- `relationships`

Resources are not identities, goals, or categories. They may be consumed, accumulated, transformed, or transferred.

### Resource Transformation

A resource transformation describes the resource inputs and outputs generated by a signal.

Example:

```text
Signal: Study English
Consumes: time, attention
Produces: knowledge
```

Example:

```text
Signal: Gym session
Consumes: time
Produces: energy, health_capacity
```

Example:

```text
Signal: Employment
Consumes: time, energy
Produces: money, knowledge, relationships
```

In the current implementation, transformation inference is foundational and rule-based. Manual metadata and stronger inference can be added later without changing the hierarchy.

### Trajectory

A trajectory is a recurring pattern of resource transformations.

Examples:

- `entrepreneurship`
- `engineering`
- `language_fluency`
- `employment`
- `health`

Trajectories bridge transformations and emergent identities. A single signal can activate a trajectory, but identity requires sustained trajectory evidence over time.

### Identity

Identity is an emergent structure.

Identity is not a goal. Identity is not a declaration. Identity is the accumulated pattern of sustained trajectories.

The current identity vector, identity fields, semantic alignments, mass, and drift remain operational for compatibility. They should be treated as the current emergent-layer implementation, not as the root ontology.

## Laws

### Law 1: Signals Create Evidence

Signals are the smallest behavioral facts Nebula processes.

### Law 2: Evidence Moves Resources

Every signal should eventually describe how resources are consumed, produced, accumulated, or transferred.

### Law 3: Repetition Forms Trajectory

A trajectory is not a single action. It is a repeated resource-transformation pattern.

### Law 4: Identity Emerges

Identity emerges from sustained trajectories. It should not be directly declared as the primary entity.

### Law 5: Mass Is Evidence

Mass represents accumulated evidence. Signals generate mass impact. Trajectories and identities store accumulated mass.

### Law 6: Momentum Is Recent Energy

Momentum represents recent activity and active trajectory energy. Momentum is temporal and must emphasize recency more strongly than lifetime accumulation.

### Law 7: Drift Has Two Levels

Signal drift is immediate displacement from one signal. Identity drift is accumulated displacement of the identity state through time.

### Law 8: Coherence Is Resource Alignment

Coherence is the degree of alignment between resource flows. High coherence means resources converge toward compatible trajectories. Low coherence means resources disperse across competing trajectories.

## Resource Model

Resources have the following minimal schema:

```json
{
  "key": "time",
  "label": "Time",
  "description": "Finite chronological capacity spent or reserved.",
  "unit": "minutes"
}
```

Resource flows have the following minimal schema:

```json
{
  "resource": "attention",
  "amount": 0.8,
  "flow_type": "consumed",
  "confidence": 0.55
}
```

Allowed flow types:

- `consumed`
- `produced`
- `accumulated`
- `transferred`

## Transformation Model

Resource transformations have the following minimal schema:

```json
{
  "transformation_id": "rt_<event_id>",
  "source_signal_id": "<event_id>",
  "consumes": [],
  "produces": [],
  "transfers": [],
  "accumulates": [],
  "inference_status": "rule_based_foundation"
}
```

Current inference is deliberately conservative. Its purpose is to create durable data structures now, not to finalize resource-flow intelligence.

## Trajectory Model

Trajectories have the following minimal schema:

```json
{
  "key": "engineering",
  "label": "Engineering",
  "description": "Transforms time and attention into technical knowledge, systems, and execution capacity.",
  "resource_pattern": {
    "consumes": ["time", "attention", "energy"],
    "produces": ["knowledge", "relationships"]
  },
  "linked_identity_field": "engineering"
}
```

The `linked_identity_field` is a compatibility bridge. It allows the existing semantic identity system to remain useful while the canonical model moves identity to the emergent layer.

## Drift Model

### Signal Drift

Signal drift is the immediate displacement generated by a single processed signal.

Stored on new events under:

```text
event.drift.signal
```

Minimal schema:

```json
{
  "magnitude": 0.0123,
  "dynamic_pull": 0.2,
  "dominant_trajectory": "engineering",
  "dominant_attractor": "engineering",
  "vector_space": "minilm"
}
```

### Identity Drift

Identity drift is accumulated displacement of the identity state through time.

Stored on new events under:

```text
event.drift.identity
```

Minimal schema:

```json
{
  "global_dominant_identity": "engineering",
  "global_dominance": {
    "engineering": 0.42,
    "fitness": 0.12,
    "be_fluent": 0.08
  },
  "accumulated_vector_dimension": 384,
  "derived_from": "aggregated_signal_drift"
}
```

For backward compatibility, the legacy drift value remains available at:

```text
event.physics_params.identity_snapshot.drift_delta
```

## Mass Model

Mass has two distinct meanings:

- `mass_impact`: mass generated by one signal.
- stored mass: accumulated evidence held by a trajectory or emergent identity cluster.

Current compatibility behavior:

- `event.physics.mass_impact` records signal-level mass impact.
- `thermodynamic_state.json` stores cluster-level mass.
- `/api/field-mass` derives identity-field mass from historical event alignment and score.

Future work should add trajectory-level mass accumulation without removing the existing identity-field mass endpoints.

## Momentum Model

Momentum represents recent active energy, not lifetime evidence.

Current compatibility behavior:

- `event.physics.momentum_burst` records signal-level momentum.
- `thermodynamic_state.json` stores current cluster momentum.
- The API decay loop reduces momentum by 15% per hour.
- Stored mass decays much more slowly than momentum.

This distinction must remain: mass is evidence; momentum is recency.

## Coherence Model

Coherence is the degree of alignment between resource flows.

High coherence:

- Resources converge toward compatible trajectories.
- Outputs of one trajectory support inputs of another.
- Time, energy, attention, money, knowledge, and relationships reinforce the same direction.

Low coherence:

- Resources disperse across competing trajectories.
- Outputs do not compound.
- Recent activity creates fragmentation rather than durable capacity.

## Compatibility Commitments

The following must remain compatible:

- `events.jsonl`
- `identity_state.json`
- `thermodynamic_state.json`
- existing API endpoints
- existing semantic alignment behavior
- existing mass and momentum behavior
- existing identity vector drift behavior

New fields may be added to events, but existing fields should not be removed.

## Current Implementation Map

- `physics_domain.py`: canonical domain models for resources, transformations, trajectories, signal drift, identity drift, and coherence placeholders.
- `nebula_processor.py`: attaches resource transformation, trajectory, and drift metadata to newly processed events.
- `api.py`: preserves legacy endpoints and exposes `/api/resources` and `/api/trajectories`.
- `config.py`: lists canonical resources and initial trajectories.

The frontend is intentionally outside the scope of this foundation phase.
